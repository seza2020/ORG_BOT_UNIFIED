# P5 — Institutional Hardening, Blocker Isolation, and Monday-Open Classification Readiness

## Scope

This phase covers the late-stage institutional hardening period of ORG_BOT_UNIFIED after broad runtime stabilization had already been achieved.

The project transitioned from open-ended debugging into controlled blocker isolation for the core problem:

the system runs but does not reliably trade.

This phase focused on governance, compile/import cleanup, blocker ranking, alpha-off root-cause isolation, and preparation for a single Monday-open classification run.

The system remained a Paper-runtime, multi-layer quant pipeline with risk-first architecture and full observability goals.

## Objective

The main goal was to determine why the system still failed to produce reliable trades after infrastructure stabilization, while preventing repeated ad hoc debugging.

Key objectives:
- close structural and runtime ambiguity
- formalize governance and change control
- identify the dominant non-trading blocker
- isolate the cause of `alpha_mode_off`
- prepare a single Monday-open classification run

The final purpose of this phase was to separate:
- live freshness defects
from
- true alpha / regime / decision-layer suppression

without reopening already-closed infrastructure questions.

## What was done

- Built a structured weekend engineering control package including freeze manifest, compile/import audit, deterministic matrix, reason-consistency audit, suppression census, Monday Open Runbook, Go/No-Go table, blocker locator, and alpha-off root-cause report.
- Repaired compile/import defects including `ops.py` future-import placement and a compatibility bridge for legacy `tbot.strategies.chop_v1`.
- Established one-ticket / one-hypothesis / one-change-type governance discipline.
- Reframed Monday market-open as a classification run rather than exploratory debugging.
- Ranked blockers and identified `alpha_mode_off` as dominant, `state_confidence_low` as secondary, and `chop_v1_no_candidate` as minor.
- Isolated the likely chain:
  - stale core context / timestamp freshness issue
  - `alpha_mode_off`
  - no trade generation

## What was confirmed

- Dominant blocker in current logs: `alpha_mode_off`.
- `state_confidence_low` is secondary, not primary.
- `chop_v1_no_candidate` remains minor.
- Compile/import drift is no longer accepted as the active blocker.
- Structural/runtime instability is no longer accepted as the active blocker.
- Latest evidence still shows stale core context.
- Monday-open live evidence is required to distinguish freshness defect vs true alpha/regime logic weakness.

## What was rejected

- infrastructure/runtime remained the main cause of no-trading
- compile/import defects still explained current non-trading behavior
- session/reason attribution defects were still active after repair
- `chop_v1_no_candidate` was the primary blocker
- `state_confidence_low` was the primary blocker
- strategy/candidate path was the first-order cause of the current no-trade condition
- broad pre-Monday threshold tuning was appropriate before in-session freshness verification
